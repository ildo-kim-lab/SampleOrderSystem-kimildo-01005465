# CURRENT_PLAN.md (이번 증분)

## 목표 (버그 수정)
주문 접수(`create_order`) 시 시료 ID를 자유 텍스트로 입력받는 대신,
등록된 시료 목록을 번호와 함께 보여주고 그중 하나를 선택하게 한다.
존재하지 않는 시료 ID로 주문을 만들 수 없게 되어, 이후 승인 시
`ValueError`로 크래시하는 문제가 원천적으로 사라진다.

## 검증할 동작
`create_order(order_registry, sample_registry, input_func, output_func)`를
호출하면:
1. 등록된 시료 목록이 번호와 함께 출력된다.
2. 사용자가 입력한 번호에 해당하는 시료의 `sample_id`로 주문이 생성된다.
3. 등록된 시료가 하나도 없으면 안내 메시지를 출력하고 주문을 만들지 않는다.

## 근거
- 사용자가 직접 실행해보고 발견한 버그: 주문 접수 시 존재하지 않는 시료
  ID(예: "S-999")를 자유 입력할 수 있었고, 그 주문을 승인하면
  `order_service.approve_order`가 `ValueError`를 던져 앱이 그대로
  크래시했다.
- 사용자가 직접 제안한 개선 방향: "가능한 ID가 선택이 되어야 한다" →
  승인/거절/출고 처리와 동일하게 번호로 목록에서 선택하는 방식 채택.

## 범위 외
- `create_order`의 시그니처가 바뀌므로(`sample_registry` 파라미터 추가),
  이를 호출하는 콘솔 라우팅(`run_order_menu`)과 기존 테스트들의 입력
  시퀀스도 이번 증분에서 함께 맞춘다 (원인과 해결책이 하나로 묶여 있어
  분리하지 않는다).

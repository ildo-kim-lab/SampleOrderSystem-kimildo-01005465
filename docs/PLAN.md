# PLAN.md — Phase별 개발 목표

이 문서는 SampleOrderSystem을 Phase 단위로 개발하기 위한 목표와, 각 Phase가 끝났을 때
**사람이 직접 콘솔에서 실행해서 확인할 수 있는 항목**을 기록합니다.

- 각 Phase는 그 자체로 동작하는 소프트웨어여야 합니다 (부분적으로 끊긴 기능이 없어야 함).
- Phase 완료 후 담당자(사람)가 직접 실행/테스트하고 피드백을 준 뒤 다음 Phase로 진행합니다.
- 요구사항의 근거는 [docs/PRD.md](PRD.md), 역할 분담은 [AGENTS.md](../AGENTS.md) 참고.

## Phase 1 — MVC 스켈레톤 (핵심 주문 흐름)

### 목표
Model(도메인)/View(콘솔 출력)/Controller(메뉴 흐름) 뼈대를 잡고, PRD.md의 핵심 상태
머신을 처음부터 끝까지 동작하게 만듭니다. 데이터는 메모리에만 유지하며(영속화는
Phase 4에서 처리), 프로그램을 재시작하면 초기화됩니다.

### 포함 기능
- 시료 등록 / 조회 / 검색
- 시료 주문(예약) — `RESERVED` 생성
- 주문 승인(재고 충분 → `CONFIRMED`, 재고 부족 → `PRODUCING`) / 거절(`REJECTED`)
- 생산 라인 처리 — FIFO 큐, 실 생산량(`ceil(부족분/수율)`)·생산 시간 계산,
  생산 완료 시 `PRODUCING` → `CONFIRMED`
- 출고 처리 — `CONFIRMED` → `RELEASED`
- 기본적인 모니터링(상태별 주문 수, 재고 수량) — 화면 고도화는 Phase 3에서 진행

### 사람이 확인할 것
1. 프로그램 실행 후 메인 메뉴가 뜨는지
2. 시료를 하나 등록하고 조회 화면에 재고와 함께 보이는지
3. 재고보다 적은 수량으로 주문 → 승인 시 즉시 `CONFIRMED`가 되는지
4. 재고보다 많은 수량으로 주문 → 승인 시 `PRODUCING`으로 전환되고, 생산 라인 메뉴에서
   대기/생산 중 정보가 보이는지, 생산 완료 후 `CONFIRMED`로 바뀌는지
5. 주문을 거절하면 `REJECTED`가 되고, 이후 상태가 바뀌지 않는지
6. `CONFIRMED` 주문을 출고 처리하면 `RELEASED`가 되는지
7. 전체 흐름(등록→주문→승인/생산→출고)이 오류 없이 끝까지 이어지는지

## Phase 2 — Dummy Data Generator

### 목표
매번 손으로 시료/주문을 입력하지 않고도 다양한 시나리오(재고 여유/부족/고갈,
여러 상태의 주문 혼합)를 바로 테스트할 수 있도록 더미 데이터 생성 기능을 추가합니다.

### 포함 기능
- 더미 데이터 생성 메뉴(또는 프로그램 시작 옵션) — 여러 시료와, 각 상태(RESERVED /
  REJECTED / PRODUCING / CONFIRMED / RELEASED)를 포함한 주문을 미리 채움
- 재고가 "여유/부족/고갈" 세 가지 상태를 모두 갖도록 시료 데이터를 구성

### 사람이 확인할 것
1. 더미 데이터 생성 실행 후 시료 조회 시 여러 시료가 재고와 함께 나오는지
2. 모니터링(주문량 확인) 화면에서 5가지 상태의 주문이 고루 섞여 보이는지
   (`REJECTED`는 집계에서 제외되는지도 함께 확인)
3. 재고가 "여유/부족/고갈" 각각인 시료가 최소 하나씩 존재하는지

## Phase 3 — Data Monitoring 고도화

### 목표
모니터링 메뉴를 실제 데이터 기준으로 정확하고 보기 쉽게 다듬습니다. Phase 1의
기본 모니터링을 개선하는 단계입니다.

### 포함 기능
- 주문량 확인: 상태별(`RESERVED`/`CONFIRMED`/`PRODUCING`/`RELEASED`) 개수·목록 표시,
  `REJECTED` 제외
- 재고량 확인: 시료별 재고 수량과 "여유/부족/고갈" 상태 표기
- 생산 라인 현황: 현재 생산 중인 시료/주문 정보, 현재까지 생산량, 대기 큐 목록(FIFO 순서)

### 사람이 확인할 것
1. Phase 2의 더미 데이터로 모니터링 화면의 상태별 개수가 실제 데이터와 일치하는지
2. 재고 여유/부족/고갈 표기가 실제 재고·주문 수량과 맞게 표시되는지
3. 생산 라인 화면에서 대기 큐가 등록 순서(FIFO)대로 보이는지

## Phase 4 — Data Persist

### 목표
시료/재고/주문/생산 큐 데이터를 JSON 파일로 저장하고, 프로그램 재시작 시 복원합니다
(`docs/PRD.md` 5.8 참고).

### 포함 기능
- 프로그램 종료 시 현재 상태를 JSON 파일에 저장
- 프로그램 시작 시 저장 파일이 있으면 로드, 없으면 빈 상태로 시작

### 사람이 확인할 것
1. 시료/주문 데이터를 만든 뒤 프로그램을 정상 종료
2. 프로그램을 다시 실행했을 때 종료 시점의 데이터(시료, 재고, 주문 상태, 생산 큐)가
   그대로 복원되는지
3. 저장 파일이 없는 상태(최초 실행)에서 오류 없이 빈 상태로 시작되는지
